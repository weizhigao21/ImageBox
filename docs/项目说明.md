## 一、项目是什么

一个**模块化**的图片处理桌面工具。每个处理能力（抠图 / 超分 / 裁剪 / …）都是一个独立可插拔模块，
共用同一套「输入 → 处理 → 输出」引擎和同一个 UI 外壳。

支持应用内检查和下载 GitHub Release 更新；Windows 发布版可以安装并重启，失败时恢复旧程序，并保留配置、模型和输出。更新源与构建说明见 [更新与发布](更新与发布.md)。

| 设计目标 | 落地方式 |
|---|---|
| 模块可插拔 | `modules/<名字>/` 暴露一个 `MODULE` 实例，`registry` 自动发现 |
| 新增能力不改 UI | UI 的参数面板由模块的 `param_spec()` 自动生成，预览页由 `preview_kinds()` 生成 |
| 批量/进度/取消一致 | 所有模块都跑在同一个 `Pipeline` + `QThread` 上，输出目录与命名规则统一 |
| 零权重也能用 | 抠图默认后端不依赖任何模型文件，装完即可出效果 |

**当前状态**

| 模块 | 状态 | 说明 |
|---|---|---|
| ✂ 抠图 `matting` | ✅ 可用 | 简易 GrabCut（零权重）/ ONNX 模型 / BiRefNet；支持原图标记主体与结果页精修 |
| ⤢ 超分 `superres` | ✅ 可用 | Real-ESRGAN x4（ONNX / Torch 双后端），分块推理防显存溢出 |
| ⬚ 裁剪 `crop` | ⏳ 占位 | 已接入框架，等实现 |

## 三、安装与启动

```powershell
python -m pip install -r requirements.txt   # 安装依赖
python run.py                               # 打开界面
python run.py --module matting              # 直接进入抠图页
```

命令行（批量处理）：

```powershell
python src\imgtool\cli.py list                                    # 列出模块与全部参数
python src\imgtool\cli.py backends                                # 查看后端与权重状态
python src\imgtool\cli.py run matting -i .\photos -o out --set output_mode=all
```

## 五、架构与一次处理的完整链路

```
        ┌──────────────── UI 层（PySide6）────────────────┐
        │ ModulePage: 参数面板 / 预览 / 文件列表 / 进度条  │
        │   ├─ ParamPanel     ← module.param_spec()       │
        │   ├─ PaintImageView ← 涂抹与标记                 │
        │   └─ ModuleWorker(QThread)                      │
        └───────────────────────┬─────────────────────────┘
                                │ params + ImageItem 列表
        ┌───────────────────────▼─────────────────────────┐
        │ 引擎层 core：Pipeline.run(items, ctx)           │
        │   解析输出目录 → 逐张调用 module.process()      │
        │   汇总进度 / 取消 / 异常兜底                     │
        └───────────────────────┬─────────────────────────┘
                                │
        ┌───────────────────────▼─────────────────────────┐
        │ 能力层 modules/matting                          │
        │   process(): 读图 → 后端推理 → 后处理 → 写文件   │
        │   backends/: simple | onnx | birefnet           │
        └─────────────────────────────────────────────────┘
```

一次「处理当前」的时序：

1. UI 收集参数（`ParamPanel.values()`），把当前图的**主体标记**放进 `item.meta["fg_hint"]`；
2. `ModuleWorker` 在子线程里创建 `Pipeline`，一次运行只解析一个输出目录（整批共用）；
3. `Pipeline` 调 `module.process(item, params, ctx)`；`params["_out_dir"]` 是本批输出目录；
4. 模块读图（中文路径安全）→ 后端推理出 alpha → 后处理（清理/阈值/羽化/去色边/描边）→
   按「输出内容」写 PNG/JPG/遮罩；结果与预览数据挂回 `item`；
5. 线程通过 Qt 信号把 `ModuleResult` 发回主线程：更新列表状态、刷新预览、启用画笔与保存按钮；
6. 单张失败不影响整批（`ModuleResult.ok=False` + 消息）。

## 六、模块开发契约

### 6.1 最小可用模块

新建 `src/imgtool/modules/<名字>/__init__.py`：

```python
from ...core.base import BaseModule, ParamSpec
from ...core.types import ImageItem, ModuleResult, TaskContext

class MyModule(BaseModule):
    name, title, icon = "mymod", "我的模块", "★"
    description = "一句话说明"
    order = 40                                   # 左侧列表排序

    def param_spec(self):
        return [ParamSpec("strength", "强度", "float", 1.0, minimum=0, maximum=10)]

    def process(self, item: ImageItem, params: dict, ctx: TaskContext) -> ModuleResult:
        out_dir = params["_out_dir"]             # 本批输出目录（已建好）
        ...                                      # 处理 item.path，写文件
        return ModuleResult(item=item, ok=True, outputs={"main": out_path})

MODULE = MyModule()
```

重启后：左侧列表自动出现该模块，参数面板、三视图预览、批量、进度、取消、预设、拖放导入全部可用，
**不需要改任何 UI 代码**。

### 6.2 关键类型

| 类型 | 用途 | 要点 |
|---|---|---|
| `ImageItem` | 一张待处理图 | `path` / `rgb` / `alpha` / `meta`（`meta` 可放任意数据，如 `fg_hint`、`result_rgb`） |
| `ModuleResult` | 一张图的结果 | `ok` / `message` / `elapsed` / `outputs`（kind → 路径） |
| `TaskContext` | 执行上下文 | `ctx.progress(done,total,msg)`、`ctx.cancelled()` |
| `ParamSpec` | 一个参数 | `kind` ∈ choice/int/float/bool/str/path/color；`depends_on` 控制联动禁用 |
| `BaseBackend` | 处理后端 | `predict(rgb, hint=None) -> alpha(0~1)`；`available()` 声明可用性 |

### 6.3 可选的进阶能力

| 能力 | 声明 | 需要实现 |
|---|---|---|
| 结果页精修画笔 | `supports_manual_mask = True` | `save_manual_mask(item, params, alpha) -> outputs` |
| 原图标记主体 | `supports_fg_hint = True` | 在 `process()` 里读取 `params["_fg_mask"]` 或 `item.meta["fg_hint"]` |

两者都为真时，UI 会分别在「原图」「结果」两个标签页挂上对应画笔工具条。

## 七、抠图模块详解

### 7.1 后端

| 后端 | 依赖 | 特点 |
|---|---|---|
| `simple` | 无 | **背景多项式外推 + 色差分割 + GrabCut**。渐变/棚拍背景实测 IoU 1.000；杂乱背景退化为「中心椭圆先验 + GrabCut」，IoU 0.914（矩形初始化只有 0.474） |
| `onnx` | onnxruntime + `.onnx` 权重 | 支持 u2net / u2netp / isnet-general-use / rmbg-1.4；权重放 `models/` 自动发现，或界面一键下载 |
| `birefnet` | torch + transformers | 质量最好，首次需联网下载权重，显存约 6–8GB |

### 7.2 三种使用方式

1. **全自动**：直接「处理当前」，不涂任何东西。
2. **原图标记主体**（建议）：在原图上涂一笔 → 涂抹只用于**定位**，
   主体轮廓仍由算法算出，再由连通性筛出「被涂到的那只主体」。
   `标记含义` 参数可切换为「严格只抠涂抹到的范围」。
3. **结果页精修**：处理完在结果上擦除/保留，`保存修改` 原地覆盖输出。

### 7.3 参数一览

| 组 | 参数 | 默认 | 作用 |
|---|---|---|---|
| 基础 | 抠图后端 | simple | simple / onnx / birefnet |
| 基础 | ONNX 权重 | auto | 自动选 `models/` 里可用的权重 |
| 基础 | 运算设备 | auto | 自动 / GPU / CPU |
| 基础 | 处理长边 | 1600 px | 仅简易后端使用，ONNX/BiRefNet 使用模型输入尺寸 |
| 基础 | 标记含义 | 整只主体 | 涂抹是「指明主体在哪」还是「就抠这一块」 |
| 基础 | 涂抹范围外扩 | 12 px | 标记范围先外扩再抠，避免切掉主体 |
| 边缘 | Alpha 阈值 | 8 | 低于该值的半透明当作全透明 |
| 边缘 | 羽化半径 | 1.5 px | 边缘柔化 |
| 边缘 | 边缘外扩/内缩 | 0 px | 正=多留边，负=收紧去白边 |
| 边缘 | Alpha 对比度 | 1.0 | >1 更实，<1 更透 |
| 边缘 | 去色边 | 开 | 反解前景色，消除边缘残留背景色 |
| 边缘 | 描边宽度/颜色 | 0 / 白 | 给主体加描边 |
| 输出 | 输出内容 | 透明 PNG | 透明 PNG / 纯色底图 / 仅遮罩 / 全部 |
| 输出 | 背景色 | 白 | 纯色底图用 |
| 输出 | 输出目录 | 自动 | 留空 = `output/matting/<时间戳>/` |
| 输出 | 文件名模板 | `{stem}_cutout` | 支持 `{stem} {name} {ext}` |
| 输出 | 覆盖同名文件 | 关 | 关闭时自动加 `_1`；涂抹保存会原地覆盖 |

## 十、已知限制与技术债

| 项 | 说明 | 计划 |
|---|---|---|
| 通用工作台页面职责偏多 | 布局+画笔+会话+预设；结果缓存已独立 | 继续拆出 `BrushController` / `PreviewController` |
| 杂乱背景的简易后端 | 只能给出「中心区域」级别的结果 | 依赖 ONNX/BiRefNet 权重；或引入显著性模型 |
| ONNX 小目标精度 | 模型固定输入尺寸，小范围标记时细节不足 | 按标记包围盒裁剪后推理再贴回 |
| 笔刷是硬边 | 适合挖掉/补回整块，不适合做软过渡 | 增加「笔刷硬度」参数 |
| 中文/路径 | 已适配中文路径；未适配网络盘断线等异常 | — |
| 打包 | 暂无 exe | PyInstaller（M6） |
