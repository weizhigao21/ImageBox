# 图片处理工具箱 —— 方案 v1

> 本文是项目立项时的方案，已按此实施完成 M0–M3。实施结果与偏差见文末。

## 1. 目标与定位

一个**模块化**的图片处理工具：每个能力（抠图 / 超分 / 裁剪 / 后续其他）都是一个独立可插拔模块，
共用同一套「输入 → 处理 → 输出」引擎和同一个 UI 外壳。
第一期只做抠图，但目录与接口按多模块设计——后续加超分、裁剪只是新增一个模块目录。

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.10.11 | 本机现有解释器，生态齐全 |
| UI | **PySide6 6.11** | 官方 Qt for Python，LGPL 便于日后分发；QThread 做后台任务 |
| 图像 | OpenCV 5 + NumPy + Pillow | 读写/色彩/后处理，内存中统一用 `np.ndarray`(RGB) 传递 |
| 推理 | **onnxruntime** 为主，torch/transformers 可选 | onnx 轻、启动快；BiRefNet 质量高但吃显存，做成可选后端 |
| 配置 | JSON（标准库） | 少依赖，参数预设可存可载 |
| 打包 | 前期 `run.py`，后期 PyInstaller | 先跑通 |

## 3. 统一模块接口（核心设计）

```python
class BaseModule(ABC):
    name: str; title: str; icon: str; description: str; order: int
    def param_spec(self) -> list[ParamSpec]        # UI 自动生成参数面板
    def preview_kinds(self) -> list[str]           # 预览标签页名称
    def process(self, item, params, ctx) -> ModuleResult
```

- 参数面板由 `param_spec()` **自动生成** → 新增模块不用改 UI 代码。
- `registry.py` 扫描 `modules\*` 自动注册 → 主窗口左侧列表自动出现新模块。
- 所有模块共用 `io_utils` 与 `pipeline` → 批量、进度、取消、输出命名行为一致。

## 5. 抠图模块 v1

**后端（可切换）**

1. `simple` —— OpenCV GrabCut + 背景多项式拟合：**不依赖任何权重，装完就能出效果**；
2. `onnx` —— u2net / isnet-general-use / rmbg-1.4 权重放在 `models\`，支持界面下载；
3. `birefnet` —— 质量最好，可选（显存约 6–8GB，2080Ti 11G 可跑）。

**参数**：后端与权重、设备（自动/CPU/CUDA）、处理长边、alpha 阈值、羽化半径、
边缘外扩/内缩、alpha 对比度、去色边、描边、输出内容（透明 PNG / 纯色底图 / 仅遮罩 / 全部）、
背景色、输出目录、文件名模板、覆盖开关。

**UI**：拖拽/选择文件与文件夹、三视图预览（原图 / 结果 / 遮罩，棋盘格透明底、可缩放）、
参数面板、预设保存与载入、任务列表（名称/尺寸/状态/耗时）、进度条与取消、一键打开输出目录。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 权重需联网下载 | 默认后端无需权重（simple），保证 UI 必定可跑；权重支持界面下载 + 手动放置 |
| Windows 中文路径 `cv2.imread` 失败 | 统一 `np.fromfile + cv2.imdecode` / `imencode + tofile` |
| 现装 onnxruntime 是 CPU 版 | 可换 `onnxruntime-gpu`，代码已按 provider 优先级自动选择 |
| transformers 5.x 大模型 API 变动 | BiRefNet 仅作可选增强，失败时报错降级到 onnx / simple |
| 显存不足（11GB） | 推理分辨率可调 + 自动回落 CPU + 预留分块处理 |

## 8. 实施结果与偏差

- **simple 后端比预期好得多**：原计划它只是"能跑通"，实际加了「背景多项式拟合 + 色差分割」
  再交给 GrabCut 细化后，光滑渐变背景下 IoU 达到 1.000；杂乱背景改用「中心椭圆先验」后
  IoU 从 0.474 提升到 0.914。（实测见 `tests/debug_busy.py` 的策略对比）
- **额外做了 CLI**：`src/imgtool/cli.py`，便于批处理和自动化验证。
- **额外做了拖拽导入**：文件/文件夹可拖到窗口任意位置（`ui/dnd.py` 的 `FileDropRelay`；
  注意 Qt 的拖放事件发给滚动区域的 `viewport()`，只对控件本身 `setAcceptDrops(True)` 收不到事件）。
- **额外做了画笔涂抹**：处理完可在结果图上手动擦除/保留，修正自动抠图的瑕疵
  （`core/mask_edit.py` 记录笔画并叠加到 alpha，`ui/widgets/paint_view.py` 负责落笔；
  涂抹按预览分辨率保存，写盘时缩放到原图分辨率，线性插值顺便带来柔和边缘）。
- **涂抹改成增量刷新**：只重算/重绘笔刷扫过的那一小块（`MaskEdit.apply_region` +
  `ImageView.update_region` 直接往 QPixmap 上补画），并且只在换图时 `fit_to_view()`。
  原先每移动一次鼠标就整图重建并把缩放弹回适应大小，放大涂抹非常卡。
- **额外做了「原图标记主体」**：在原图上涂一笔，涂抹只用于**定位**——
  主体轮廓仍由「背景外推 + 色差分割 + GrabCut」算出，涂抹负责挑出被涂到的那只主体
  （`hint_mode=subject`，实测 IoU 0.998）或限定范围（`hint_mode=region`）。
  早期版本把整片涂抹范围直接当前景，结果等于矩形裁剪 + 带背景，已修正。
- **未做**：自定义标题栏、多语言、分块推理（显存足够时不需要）。
