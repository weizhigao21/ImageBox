### 1. M0–M3：骨架 → UI → 抠图后端 → CLI

**方案先行**：确认了 Python + PySide6（LGPL 好分发）、先做零权重 `simple` 后端打通链路、
带 CLI 批处理入口。方案存档在 [方案.md](方案.md)。

**落地**：
- `core/`：`BaseModule` / `ParamSpec` / `registry` 自动发现 / `Pipeline` 批量引擎 / `io_utils`（中文路径安全）
- `ui/`：主窗口 + 左侧模块列表 + 通用工作台 `ModulePage`（参数面板由 `param_spec()` 自动生成）
- `modules/matting/`：`simple` / `onnx` / `birefnet` 三个后端 + 后处理（羽化/去色边/描边）
- `cli.py`：`list` / `backends` / `run` 三个子命令，任意参数用 `--set key=value` 覆盖

**过程中修掉的问题**

| 现象 | 原因 | 改动 |
|---|---|---|
| `decontaminate` 报广播错误 `(600,800,3) vs (600,800)` | `cv2.boxFilter` 对 3 通道图像和 1 通道权重返回通道数不同 | 权重扩成 3 通道再滤波 |
| 简易后端抠出来一坨（IoU 0.525） | 直接用整图矩形跑 GrabCut，阴影和背景杂色被当主体 | 改为「边缘像素建模背景」，无效 |
| 换成向内外扩散的背景估计，更差（0.269） | 迭代归一化卷积发散，且渐变背景外推不准 | 放弃 |
| 改用**边缘多项式拟合**外推背景 + LAB 色差 + Otsu | —— | **IoU 0.525 → 1.000** |
| 杂乱背景退化到 IoU 0.474 | 矩形初始化把画面四周杂色当成可能前景 | 换成**中心椭圆先验**（范围外确定背景），**0.474 → 0.914** |

> 这段对比脚本保留在 `tests/debug_busy.py`，可以随时复跑五种初始化策略。

**验证**：`tests/smoke_test.py` 通过（光滑背景 IoU 1.000 / 杂乱背景 0.914），
`tests/ui_smoke.py` 离屏跑通「导入 → 抠图 → 预览 → 保存」并出截图。

### 2. 拖放导入：拖到界面上没反应

**现象（用户反馈）**：图片不能拖进 UI。

**原因**（两个叠加）：
1. 我只给文件列表开了拖放，拖到预览区、参数面板本就没反应；
2. 就算拖到文件列表上也没用 —— `QTableWidget` / `QGraphicsView` 这类滚动区域，
   拖放事件实际发给 **`viewport()`**，只对控件本身 `setAcceptDrops(True)` 收不到事件。

**改动**：新增 `ui/dnd.py` 的 `FileDropRelay`，同时给控件和它的 viewport 打开并监听拖放；
挂到「主窗口 / 模块页 / 文件列表 / 三个预览视图」四个落点。窗口级兜底覆盖其余空白区域
（Qt 派发拖放时会从鼠标下的控件往上找第一个接受拖放的控件）。顺带做了：拖入时状态栏提示、
在占位模块上拖放自动切到抠图页、文件夹递归展开、重复拖不重复添加、非图片忽略。

**验证**：`tests/dnd_test.py` —— 四个落点 + 边界情况全绿。

> 注意：PySide6 里**用 Python 手工构造的 `QDragEnterEvent`，`mimeData()` 会退化成裸 `QObject`**
> （真实系统拖放不受影响），所以测试改为直接调用 `FileDropRelay.eventFilter()` 验证处理逻辑，
> `acceptDrops` 开关单独断言。

### 3. 结果页精修画笔（擦除 / 保留）

**需求**：抠完之后能手动修掉多余部分。

**实现**：`core/mask_edit.py` 记录笔画（`0=没涂 / 1=擦除 / 2=保留`），叠加时
`alpha*(1-擦除)` 再 `max(保留)`；`ui/widgets/paint_view.py` 负责落笔并画笔刷光标（擦除红圈、保留绿圈，Alt 反向）；
模块侧新增 `BaseModule.save_manual_mask()` 钩子，抠图模块抽出 `write_outputs()` 与正常输出共用，
**涂抹保存原地覆盖同一批文件**，不产生 `_1` 副本。

**验证**：`tests/brush_test.py` 单测 + 真实鼠标事件 + 落盘校验。

### 4. 「画笔涂抹」点不动

**现象（用户反馈）**：鼠标选择不了画笔涂抹。

**原因**：我把整条画笔工具条跟着「当前图有没有处理结果」一起 `setEnabled(False)` 了 ——
还没处理时复选框就是灰的，点了毫无反馈，看起来像坏了。

**改动**：画笔开关与笔刷设置**始终可点**；点了但还不能用时给出明确提示
（「请先『处理当前』，再用画笔修掉多余部分」）；勾选状态会记住，处理完成后自动生效。

**验证**：`brush_test.py` 增加 `isEnabled` + `QApplication.widgetAt()` 遮挡检测 +
点击后状态断言。

### 5. 原图标记主体：第一版做错了

**需求**：涂抹要在**原始图片**上涂，涂的范围是「我要抠出来的地方」。

**第一版实现**：把整片涂抹范围标成 GrabCut 的「可能前景」，范围外标成「确定背景」。

**现象（用户反馈）**：涂抹的部分没有识别主体，是**直接裁剪**，而且**还有背景**。

**原因**：正反两个颜色模型都混进了背景色 —— 涂抹的色带里既有主体也有背景，
而范围之外又包含了主体的另一半，两个模型高度重叠，GrabCut 分不开，于是原样吐回整块。

**改动**（两层）：
1. 后端不再拿涂抹当掩码：`_rough_foreground()` 正常路径优先，涂抹只在「背景不光滑、
   全自动跑偏」的兜底场景才当搜索区；
2. 新增 `postprocess.apply_hint_subject()`：对 alpha 做连通域分析，
   **只保留与涂抹区域相连的成分** —— 涂在主体任意一处，整只主体都留下，画面里别的物体不带出来。

同时定清语义并做成参数 `标记含义`：

| 选项 | 行为 | 实测 |
|---|---|---|
| 涂一下 → 抠出整只主体（默认） | 涂抹只用于定位 | **IoU 0.998** |
| 严格只抠涂抹到的范围 | 涂抹范围就是边界（配合「涂抹范围外扩」） | 主体 21729px vs 涂抹包围盒 24734px，边界是主体弧线 |

> 中途还试过「在涂抹范围内做局部 Otsu 色差分割」，反而把主体切残（IoU 0.617），已弃用。

**验证**：`tests/fg_hint_test.py` —— 含「不是矩形裁剪」的回归断言：
取主体最宽处与上缘的行宽（101px / 34px），矩形裁剪时这两行会一样宽。

### 6. 放大涂抹非常卡 + 缩放被弹回

**现象（用户反馈）**：在放大状态下涂抹，图片和显示大小老是变，涂抹非常卡顿。

**原因**（同一处代码）：
1. `ImageView.set_qimage()` 每次都调 `fit_to_view()` → **每移动一次鼠标，缩放就被弹回适应大小**；
2. 每次移动都整图重算 alpha（float32 大数组运算）+ 整张 RGBA→QImage→QPixmap 重建。

**改动**：
- `set_qimage(image, fit=None)`：只在**尺寸变化/换图**时重新适应窗口，涂抹刷新传 `fit=False`；
- 新增 `MaskEdit.apply_region()` 与 `ImageView.update_region()`：
  **只重算、只重绘笔刷扫过的那一小块**（直接往持久 QPixmap 上补画，再 `item.update(描边矩形)`）；
- 原图标记的绿色叠加同样改成增量（掩码按图缓存，只更新脏矩形）。

**实测**

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 2048px 预览每次移动 | 整图重建（几十 ms）+ 缩放弹回 | **2.0 ms** |
| 3000×2000 原图（预览降到 2048×1365） | 同上 | **4.9 ms** |
| 放大 3 倍后涂抹 | 每笔都跳回适应大小 | 缩放 0.41 → 0.41 不变 |

**顺带抓到一个我自己引入的真 bug**：空涂抹时 `MaskEdit.apply()` 会把 `base_alpha` **原样返回**，
而我把它当成可写的显示缓冲 `composite` —— 一增量写入就把底图写坏了，
于是**撤销之后擦除痕迹还在**（测试里表现为「差异像素 6388」）。
修法：`apply()` 始终返回新数组，不再有别名。

**验证**：`brush_test.py` / `fg_hint_test.py` 各加了「缩放保持 + 每次移动耗时上限」的断言。

### 7. 按住滚轮键平移图片

**需求（用户反馈）**：按住滚轮可以移动图片。

**原因**：左键本来靠 `ScrollHandDrag` 平移，但一开画笔我就把 dragMode 关成 `NoDrag`，
于是左键去涂抹了，**图片彻底移不动**，放大后尤其难受。

**改动**：在 `ImageView` 里手写中键平移（不依赖 dragMode，与涂抹互不干扰）：
中键按下优先于涂抹判断 → 拖动改滚动条 → 松手恢复画笔十字光标；平移会关掉「自动适应窗口」，
窗口变化不再把视图弹回去。

**验证**：`brush_test.py` 增加一节 —— 平移生效、**不误涂抹**、不改变缩放、光标正确恢复、
关闭画笔后左键仍可平移。

> 顺带修了测试辅助函数的不忠实之处：Qt 鼠标松开事件里 `button()` 应该是**被松开的那个键**
> （原来填 `NoButton`），否则中键松开识别不到、握拳光标不回位。

## 经验教训

1. **Qt 滚动区域的拖放/鼠标事件发给 `viewport()`**，只对控件本身设置是无效的。
2. **不要把整条工具条跟着「有没有结果」一起禁用** —— 用户点不动又没有反馈，等于功能坏了。
   正确做法是保持可点 + 明确提示。
3. **别让函数的返回值可能和入参是同一个对象**（`apply()` 空编辑返回原数组），
   调用方一旦把它当可写缓冲就会写坏源数据。这次是靠测试里的「撤销后回到原值」抓出来的。
4. **测试必须覆盖真实事件路径**。早期画笔测试直接调 `page._on_stroke_begin(...)`，
   绕过了鼠标事件，所以「鼠标点不动」「缩放弹回」这类问题一个都测不出来；
   现在统一发真实 `QMouseEvent`（`tests/ui_helpers.py`）。
5. **性能问题要量，不要猜**。`per_move` 从"感觉卡"变成 2.0ms 这个数字之后，
   才知道该优化的是整图重建和 `fit_to_view()`，而不是笔刷算法。
6. **语义要先和用户对齐再写代码**。第 5 条那一版返工，根子是我把「涂哪里=抠哪里（硬边界）」
   和「涂一下=指出主体在哪（识别轮廓）」当成了同一件事。
